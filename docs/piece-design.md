# 棋子设计手册（v12 · 事件总线版）

> 这份文档回答一个问题：**怎样让一枚棋子不只是「攻击力更高的刀客」，而是构筑系统里的一个零件？**
> 方法借自《大巴扎》（The Bazaar）的物品设计，但数值、棋子、兵书全部是本作自己的。
> 文的最后有验证数据：三条构筑路线在对等造价下打纯数值阵的胜率。

---

## 1. 三条设计律

1. **一枚棋子至少要改变一件「事」，而不只是改变一个「数」。**
   `相邻 +20% 攻击` 是数；`相邻棋子每 3 次命中，让这枚棋子提前出手` 是事。
2. **空间是成本。** 棋子占格、引擎只影响相邻、需要贴着谁才成立——摆位才是构筑。
3. **链条要有头有尾。** 触发源 → 传递 → 收益，三段缺一段，这条路线就是废的。

判断一枚棋子是否合格，只问四句：

- 它产生什么事件？（`hit` / `hurt` / `burn_tick` / `trigger` / `kill`）
- 谁消费这个事件？
- 它把什么资源换成了什么资源？（伤害↔护盾↔冷却↔充能↔金币）
- 玩家会不会为了它重排棋盘？

## 2. 六种功能定位

不再用「战士/法师/射手」分类——那是外观。按**在构筑里干什么**分类：

| 定位 | 职责 | 本作棋子 |
|---|---|---|
| 输出（dps） | 造成主要伤害 | 刀客、弓手、骑将、连弩车、雷术师 |
| 触发（trigger） | 制造事件，让别人开始工作 | 刀客、连弩车、雷术师、医者、骑将 |
| 转换（convert） | 把一种事件/状态换成另一种收益 | 火术师（命中→燃烧）、霜术师（命中→减速） |
| 引擎（engine） | 定义规则、累积事件、改冷却 | 战鼓旗、火盆旗、机关人、风助、将台 |
| 支援（support） | 让别的棋子更频繁/更安全地工作 | 医者、盾卫、风助 |
| 成长（grower） | 把前期投入变成后期强度 | 将台（战斗中成长）、兵书经济类 |

一枚棋子可以同时属于多类。数据里写在 `roles` 字段（`js/data.js`），UI 只用它做提示，不影响结算。

## 3. 标签：只引用关键词，不引用棋子名

`js/data.js` 的 `TAGS`：

| 标签 | 含义 | 目前持有者 |
|---|---|---|
| `melee` | 近战 | 刀客、骑将、盾卫 |
| `ranged` | 远程 | 弓手、将台、霜术师、雷术师、火术师、连弩车 |
| `fire` | 火焰 | 火术师、火盆旗 |
| `frost` | 霜 | 霜术师 |
| `machine` | 机械 | 机关人、连弩车 |
| `heal` | 治疗 | 医者 |
| `shield` | 护盾 | 盾卫 |
| `flag` | 旗帜（无血挂件） | 风助、机关人、战鼓旗、火盆旗 |

钩子支持两个标签位：

```js
on: {
  hit: {
    scope: 'team',   // self / adjacent / team
    tag: 'machine',  // 只有「机械」棋子触发时才成立
    to: 'melee',     // 只给「近战」上效果（haste / charge 用）
    do: 'charge', v: 1.0, need: 3
  }
}
```

规则只有一条：**能写标签就不要写棋子 id**。以后加「机械弩炮」，机关人不用改就能吃到它的命中。

兵书同理：`qixie`（每有一枚【机械】→ 全队攻击 +8/12/16%）、`tongpao`（每有一枚【旗帜】→ 全队血量 +6/9/13%）、`xuezhai`（我方挨打 → 全体【近战】加速）。

## 4. 三条验证过的构筑链

### 4.1 高频攻击（连击）

```
刀客（每 3 刀提前 0.9 秒）
   → 战鼓旗（全队每 3 次命中，出手者补一刀 1.3×）
   → 风助（任何触发 → 全队 +50% 攻速 2.5 秒）
   → 更多命中 → 回到第一步
```
- **触发源**：刀客、连弩车（自身每 3 箭提前 0.4 秒）
- **传递**：战鼓旗的 `hit` 计数器
- **收益**：多出来的攻击次数（不是攻击力）
- **断链后果**：没有战鼓旗，刀客只是「攻速快一点」；没有风助，战鼓旗的收益上限掉一半。

### 4.2 燃烧连锁

```
火术师（自身命中 + 相邻友军命中 → 挂燃烧，0.30 / 0.60）
   → 机关人（燃烧跳伤 → 全队冷却 −1.1 秒）
   → 出手变快 → 更多命中 → 更多燃烧
   → 火盆旗（燃烧跳伤 → 把燃烧扩散给旁边敌人）
```
- **上限**：单个目标身上的燃烧秒伤封顶 **13% 最大生命**（`CFG.burnCap`），防止无限叠。
- **断链后果**：只有火术师 → 燃烧是「慢慢掉血」；补上机关人才变成「越烧越快」。
- 这条链是本作最容易失控的一条：`burn_tick → charge → 更多 hit → 更多 burn_tick`，靠 `limits.rate`（每个引擎每秒 1~4 次）+ 事件深度上限 3 层压住。

### 4.3 承伤反击（这一版新做的）

```
骑将（自己挨打 → 立刻反击 22% 伤害）
盾卫（相邻友军挨打 → 反弹 35% 的伤害）
   → 医者（治疗，把战斗拖长）
   → 拖得越久，反击次数越多
```
- 这是**把「承伤」换成「输出」**的转换链，也是唯一一条不需要攻速的路线。
- 盾卫自己没有攻击力，所以反弹按「挨了多少」算（`reflect: true`），否则它一辈子打 0。
- **断链后果**：没有医者，骑将 11 秒就倒，反击次数不够；没有盾卫，只有骑将一个人在还手。


### 4.4 两种持续伤害：燃烧 与 毒（照《大巴扎》的结构）

这一版之前，**两者其实是同一个东西**——毒的伤害直接写进 `burnDps`，毒师的光环是死代码，
苗疆蛊的「毒」被动其实是「更多燃烧」，附魔·毒更是从来没生效过。

《大巴扎》的处理方式是：燃烧和毒**都是堆层数的持续伤害，但结算节奏和衰减规则完全不同**。
我们按它的结构重做（数值仍用我们自己的尺度）：

| | 燃烧 | 毒 |
|---|---|---|
| 结算 | **每秒 2 次** | 每秒 1 次 |
| 每次伤害 | = 当前燃烧值 | = 当前毒值 |
| 结算后 | **衰减 35%**（大巴扎是每跳 −1 层） | **不衰减** |
| 护盾 | 有护盾时**伤害减半** | **无视护盾** |
| 解除 | 自己会烧完 | **只能靠治疗量抵消毒** |
| 事件 | 每次结算派发 `burn_tick`，喂机关人 / 火盆旗 | 不派发任何事件 |
| 来源 | 火术师、火盆旗、附魔·焰、江东火（+40% 燃烧伤害） | 毒师、附魔·毒、苗疆蛊被动 |

**为什么这样才好**：

- 燃烧是**爆发**：第一次结算最疼，之后越来越轻。所以它奖励「在燃烧值最高的时候继续补刀」，
  而不是「挂上就不用管」。反复命中续火，才能一直烧。
- 毒是**熬**：不衰减、无视护盾，但每秒只结算一次，速度慢；治疗能直接把毒抵掉，
  所以毒怕奶、不怕盾。它和燃烧因此不是同一条线上的强弱，而是**两种解法**。
- 只有燃烧派发事件，所以只有燃烧能进「燃烧引擎」（机关人充能、火盆旗扩散），
  毒是一条独立的伤害线——这也是为什么毒不需要事件：它靠的是「对面解不掉」。

**数值**：燃烧值上限 10% 最大生命，每次施加按攻击的 50% 折算；毒上限 10%/秒，
附魔·毒把攻击的 6% 转成毒，单次治疗量的 60% 拿去抵消毒。

**同时修掉**：附魔·毒的 `fx.poison` 从没被 `hit()` 读过（安慰剂）、毒师光环被 `refreshAuras` 过滤掉、
苗疆蛊的被动偷偷加在 `pieceBurn` 上、江东火的「灼烧伤害 +40%」以前其实是「每次命中附带燃烧」。

## 5. 棋子卡（12 枚核心）

> 数值在 `js/data.js`，这里只写「它改变了什么规则」。完整数值见代码。

| 棋子 | 格 | 定位 | 规则（不是数值） | 最适合 | 也被谁需要 |
|---|---|---|---|---|---|
| 刀客 | 2×2 | 输出/触发 | 每 3 次命中，自己提前 0.9 秒出手 | 战鼓旗、风助 | 火术师（相邻点火） |
| 弓手 | 2×2 | 输出 | 抛射点名最后排——它的规则是**选目标** | 盾卫保护 | 任何怕后排被点名的阵 |
| 骑将 | 2×3 | 输出/触发 | 自己挨打就反击 22% | 医者、盾卫 | 承伤反击整条链 |
| 将台 | 3×3 | 引擎/输出 | 场上任何触发 → 全队冷却 −0.5 秒 | 医者、连弩车（高频触发） | 慢速大阵 |
| 医者 | 1×1 | 支援/触发 | 治疗本身算一次「触发」 | 风助、将台 | 承伤反击的续航 |
| 盾卫 | 1×2 | 支援 | 相邻友军挨打 → 反弹 35% | 骑将、弓手 | 任何「脆皮贴着坦克」的摆法 |
| 霜术师 | 1×1 | 转换 | 命中 → 减速 35% | 慢速大件 | 拖时间的阵 |
| 雷术师 | 1×2 | 输出/触发 | 命中 → 连锁 2 人 | 聚团敌人 | 溅射阵 |
| 火术师 | 1×2 | 转换 | 自身 + 相邻友军命中 → 燃烧 | 刀客、连弩车 | 燃烧整条链 |
| 风助 | 1×1 | 支援/引擎 | 任何触发 → 全队 +50% 攻速 2.5 秒 | 医者、连弩车 | 高频整条链 |
| 机关人 | 1×1 | 引擎 | 燃烧跳伤 → 全队冷却 −1.1 秒 | 火术师 | 燃烧整条链 |
| 连弩车 | 1×1 | 输出/触发 | 攻速 2.8 秒；每 3 箭自己提前 0.4 秒 | 战鼓旗、机关人 | 高频整条链 |
| 战鼓旗 | 1×1 | 引擎 | 全队每 3 次命中 → 出手者补一刀 | 刀客、连弩车 | 高频整条链 |
| 火盆旗 | 1×1 | 引擎 | 燃烧跳伤 → 扩散给旁边 | 火术师 | 燃烧整条链 |

**单独用也有价值**：刀客不靠战鼓旗也能打；火术师不靠机关人也能挂燃烧。
**凑齐才有额外收益**：上面三条链的第三段。

## 6. 升级：三种，不要都做成数值

每枚棋子 3 个流派（2 级三选一、3 级二选一），尽量让其中至少一个是**机制型**：

| 类型 | 例子 | 什么时候用 |
|---|---|---|
| 数值型 | 刀客「快刀」攻击间隔 −25% | 新手棋子，别让人算不过来 |
| 机制型 | 刀客「连斩」25% 概率立刻补一刀（每秒最多 2 次） | 要改变「它和谁配合」 |
| 分支型 | 火术师「烈焰 / 火雨 / 引燃」——强度、范围、速度三选一 | 让同一枚棋子进不同流派 |

本版补上了骑将、将台缺的流派（之前这两枚 2 级合成后没有三选一，是个洞）：

- 骑将：铁骑（反击 22%→42%）/ 重甲（血 +35%）/ 横扫（溅射 +1）
- 将台：军令（充能 0.5→1.0）/ 大纛（改成全队加速）/ 楼台（射程 +1）

## 7. 怎么验证（`tools/sim.mjs`）

无头模拟器：把两套构筑放进同一场战斗，跑 N 局算胜率。

```bash
node tools/sim.mjs --n 24 --day 6     # 默认跑 D3 / D6 / D9
```

关键点：

- **双向对打**：每局各打一次「A 在下半场」「A 在上半场」，再合并统计。棋盘上下半场有先手差异（见 §8），单向对打会把位置偏差算成构筑强度。
- **同造价**：构筑按「牌面价 × 等级」对齐到 ±10%，否则测的是谁更贵。
- **布阵脚本**：`near` 字段声明「必须贴着谁」（火术师贴着刀客、盾卫贴着骑将），否则引擎可能根本不在联动范围内，测出来的是「没摆对」而不是「设计不行」。

### 本版验证数据（D6，18 格，各 24 场双向）

| 构筑 | vs 纯数值 | 战斗时长 | 事件量 |
|---|---|---|---|
| 高频攻击（刀客+连弩+战鼓+风助+医者） | **52%** | 12 s | hit 79 / trigger 24 |
| 燃烧连锁（刀客+火术+机关人+火盆旗+医者） | **54%** | 14 s | burn_tick 98 / trigger 106 |
| 承伤反击（骑将+盾卫+医者+刀客） | **60%** | 22 s | hurt 70 / trigger 7 |
| 纯数值 vs 纯数值（校验用） | 50% | 15 s | — |

D3 / D9 复测：高频 50 / 41，燃烧 63 / 44，承伤 44 / 59。
结论：三条路线都在 **41%~63%** 区间——都能玩，没有一条碾压纯数值，也没有一条是废的。

> 目标区间是 50~60%。高于 70% 说明这条链白送强度；低于 40% 说明它只在「摆对了」的时候才成立，实战里没人会为你摆。

## 8. 这一版顺手修掉的五个引擎 bug

模拟器第一次跑就暴露了它们，全部是真实影响对局的：

1. **大招充能按伤害绝对值**：等级一高，一次普攻就充满，全场大招连锁 → 0.7 秒结束战斗。改成按「占最大生命的比例」充能，单次封顶 12%。
2. **敌人的大招结算在我方头上**：`cast()` 里写死 `b.p`，敌人放治疗/护盾反而治我方。改成按 `p.side` 取 allies/foes。
3. **同归于尽永远是我方赢**：`tick` 固定先结算我方，后结算的一方已经死了。改成按帧交替 + 死亡延迟到帧末统一结算（`resolveDeaths`）。
4. **进化把钩子数组覆盖成对象**：火术师有两个 `hit` 钩子（自身点燃 + 相邻点燃），一进化就变成 `{0:...,1:...,v:0.65}`，整套燃烧静默失效。修好后燃烧流胜率从 0% 直接回到 92%（再调数值到 54%）。
5. **盾卫反击打 0 伤害**：它没有攻击力，`counter` 用自身 dmg 结算就永远是 0。补了 `reflect`（按挨打伤害反弹）。

## 9. 设计检查清单

新加一枚棋子，逐条过：

- [ ] 它产生/消费哪个事件？写在 `on` 里了吗？
- [ ] 只用标签能描述它的联动对象吗？还是写死了某个棋子 id？
- [ ] 单独上场时有用吗？（不许出现「没有 X 就完全废物」）
- [ ] 凑齐一条链后，收益是**次数/频率/转化**，还是又回到「攻击力 +X%」？
- [ ] 它逼玩家改摆位吗？（要贴着谁 / 占几格 / 站第几排）
- [ ] 有 `limits.rate` 或 `need` 吗？会不会和机关人、战鼓旗组成无限循环？
- [ ] 三个流派里，至少一个是机制型吗？
- [ ] 在 `tools/sim.mjs` 里加一条对局，胜率落在 40%~65% 吗？

## 10. 已知问题 / 下一步

- **承伤反击偏强**（60%）：`hurt` 事件让坦克同时吃到「挨打充能」和「反击」两份收益，下一版考虑让 `hurt` 触发也有每秒总次数上限。
- **机关人、战鼓旗这类无血挂件没有「被打掉」的风险**：目前靠数值（收益小）平衡，长期应该给「挂件被摧毁」的规则。
- **AI 还不会主动摆联动**：`evalBoard` 已经给引擎加了「贴着输出才值钱」的权重、给承伤反击加了估值，但还没有「为了火术师去凑燃烧」的规划；下一步让 AI 按标签统计阵型。
- **兵书和棋子的标签还没有互相引用**：现在只有 3 本标签兵书，下一步让「火焰」兵书影响带 `fire` 的棋子。
